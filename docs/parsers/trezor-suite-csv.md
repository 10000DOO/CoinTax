# Trezor Suite — 계정 내역 CSV 포맷 (실측)

| 항목 | 내용 |
|------|------|
| 실측일 | 2026-08-14 |
| 샘플 (로컬 only) | `docs/samples/raw/Trezor Safe7/…/Bitcoin_1_…csv` · `Ethereum_1_…csv` |
| 파일 형식 | **`.csv`** UTF-8 (BOM 있을 수 있음) |
| 특수 | **1행 헤더** (메타 행 없음 — OKX 와 다르다) · **따옴표로 감싼 쉼표** 있음 |
| 타임존 | `Timestamp` 가 **유닉스 초** (타임존 무관) |
| 성격 | **개인 하드웨어 지갑 · 온체인 내역** (거래 체결 아님) |
| 파서 | `CoinTax/Import/Parsers/Trezor/TrezorSuiteCSVParser.swift` |

> 지갑 주소·TXID 포함 → git 커밋 금지. 앱은 저장 시 **SHA-256 앞 16자**로 바꿔 넣는다.

---

## 1. 파일 구조

```text
행1: Timestamp,Date,Time,Type,Transaction ID,Fee,Fee unit,Address,Label,Amount,Amount unit,Fiat (USD),Other
행2~: 데이터
```

**계정(체인)마다 파일이 따로 나온다.** 파일명이 `Bitcoin_…` / `Ethereum_…` 형태라
네트워크를 파일명에서 읽는다.

`Fiat (USD)` 는 Trezor Suite 의 통화 설정에 따라 `Fiat (KRW)` 등으로 **헤더가 바뀐다.**
그래서 코드는 `Fiat (` **접두만** 본다.

`Fiat (USD)` 값에 천 단위 쉼표가 들어가 **따옴표로 감싸인다.** 따옴표를 모르는 분해기로
읽으면 그 행부터 열이 통째로 밀린다 (`CSVUtil.parseLines` 는 따옴표 상태기를 갖고 있다).

## 2. 컬럼

| 헤더 | 의미 | 비고 |
|------|------|------|
| `Timestamp` | **유닉스 초** | 이걸 **먼저** 쓴다 (아래 §3) |
| `Date` / `Time` | 사람이 읽는 시각 | 로캘 표기 (`2026. 8. 12.`) — 기기 설정에 따라 다르다 |
| `Type` | `RECV` / `SENT` | **방향 판정에 쓰면 안 된다** (§4) |
| `Transaction ID` | 온체인 TXID | **같은 값끼리 묶어야** 무엇을 주고받았는지 보인다 |
| `Fee` | 가스비 | 받은 행(RECV)에는 없다 |
| `Fee unit` | 가스비 자산 | `Fee` 가 0이면 **빈 칸** |
| `Address` | 주소 | **받은 행에는 내 지갑 주소**, 보낸 행에는 상대 주소 → **방향의 근거** |
| `Label` | 사용자 메모 | 실측 전부 빈 칸 |
| `Amount` | 수량 | **부호 없음** (방향은 `Address` 로 판정) |
| `Amount unit` | 자산 티커 | ERC-20 토큰 티커 그대로 |
| `Fiat (USD)` | 시세 환산액 | **빈 칸이면 Trezor 가 시세를 모르는 토큰** (§5) |
| `Other` | — | 실측 전부 빈 칸 |

실측 `Type` 값: `RECV`, `SENT` — 이 둘뿐.

---

## 3. 시각 — 유닉스 초를 먼저 본다

`Date`/`Time` 은 로캘 표기라 기기 설정에 따라 달라진다. 여기서 **하루가 밀리면 과세연도
귀속(2027-01-01 경계)이 통째로 틀어진다.** 그래서 순서를 고정했다.

```text
1) Timestamp (유닉스 초) 가 있고 > 0 이면 그것을 쓴다     ← 타임존·로캘 무관
2) 없으면 Date + Time 을 KST 로 읽는다
   허용 형식: "yyyy. M. d. HH:mm:ss" / "yyyy-MM-dd HH:mm:ss" / "yyyy/MM/dd HH:mm:ss"
3) 둘 다 실패하면 그 행은 건너뛰고 경고를 남긴다
```

---

## 4. 방향 판정 — `Type` 이 아니라 `Address` 로 가른다 ★

**거래소 파일과 가장 크게 다른 점이고, 틀리면 보유 수량이 통째로 뒤집힌다.**

한 트랜잭션이 토큰을 내보내면서 다른 토큰을 받으면 **두 행 모두 `SENT` 로 찍힌다.**
그 트랜잭션을 「보낸」 주체가 내 지갑이기 때문이다. 디파이 예치가 정확히 이 모양이다.

```text
1) RECV 행들의 Address 를 **전부** 모아 「내 주소 집합」으로 둔다
2) RECV 행 = 들어온 것(deposit)
3) SENT 행인데 Address 가 내 주소 집합에 있으면 = 들어온 것 (디파이 예치의 받는 몫)
   그 밖의 SENT 행 = 나간 것(withdrawal)
```

⚠️ **최빈 주소 하나만 쓰면 안 된다 (7차 감사 D-2).** 비트코인 계열 지갑은 **받을 때마다
새 주소를 만든다**(HD 지갑의 기본 동작). 실사용 파일에서 받은 내역 13건이 8개 주소로
흩어져 있었고, 최빈 주소(4회)만 내 것으로 보면 **나머지 9건이 「보낸 것」으로 뒤집혀**
보유가 실제의 −53% (음수)가 됐다. 받은 행의 주소는 **정의상 전부 내 것**이다.

**내 주소를 못 찾으면 가져오지 않고 막는다** (`parserReject`). 받은 내역이 한 건도 없는
파일이 그렇다. `Type` 으로만 판정하면 **받은 영수증 토큰을 보낸 것으로 읽어** 보유가
틀어지므로, 조용히 넘어가는 것보다 막는 쪽이 안전하다.

---

## 5. 트랜잭션 묶음 → 분류

`Transaction ID` 로 묶은 뒤 이렇게 나눈다. 결과는 이벤트의 `sourceKind` 로 남는다.

| 상황 | `sourceKind` | 처리 |
|------|--------------|------|
| 수량이 움직인 행이 **하나도 없음** (금액 0 + 수수료만) | `trezor-gas-only` | 가스비만큼 출금 + **소멸 표시**(`lostForever`). 토큰 사용 승인(approve) 등 |
| 들어온 행 · 나간 행이 **둘 다 있고**, 들어온 쪽만 시세 없음 | `trezor-defi-deposit` | 디파이 예치로 보이는 짝 |
| 둘 다 있고, **나간 쪽만** 시세 없음 | `trezor-defi-withdraw` | 디파이 인출로 보이는 짝 |
| `Fiat` 가 빈 칸인 행 | `trezor-unpriced-token` | 시세를 모르는 토큰 (예치 영수증·LP 토큰) |
| 그 밖 | `trezor` | 단순 입출금 |

**「시세 없음」의 근거는 `Fiat` 열이 비었다는 사실 하나다.** 우리가 토큰 이름을 보고
넘겨짚지 않는다. 예치 영수증 토큰은 Trezor 도 시세를 모르므로 이 열이 빈다.

### 가스비는 트랜잭션당 한 번만 붙인다

행마다 `Fee` 가 중복 표기될 수 있어 **합산하지 않고 최댓값**을 쓴다.
그리고 **나가는 행 하나에만** 붙인다 — 여러 행에 나눠 붙이면 이중 계상이다.

**붙이는 조건이 하나 더 있다: 가스 자산과 보내는 자산이 같아야 한다.**
USDT 를 보내며 ETH 로 가스를 내면 자산이 다른데, 수량 규칙 한 벌
(`LedgerDelta.withdrawalFeeQuantity`)은 「수수료 자산이 보내는 자산과 다르면 장부를
건드리지 않는다」이므로 **가스가 통째로 사라진다** (7차 감사 D-3 — 실사용 이더리움 파일에서 6건).

그래서 아래 두 경우에는 **별도 출금 이벤트**로 뺀다.
- 나가는 행이 없다 (받기만 한 트랜잭션)
- 가스 자산이 보낸 자산과 다르다 (토큰 전송의 ETH 가스)

빼지 않으면 장부 수량이 체인과 어긋난다.

## 6. 세무 처리는 파서가 정하지 않는다

파서는 **사실만 읽고**, 판단이 필요한 자리를 **경고로 드러낸다.**

| 경고 | 근거 |
|------|------|
| 가스비만 나간 트랜잭션 N건 — 그 취득원가는 소멸 처리 (세액이 커지는 방향) | 백서 U-11 |
| 시세를 알 수 없는 토큰 — 취득가 0원, 원화 환산 안 됨 | — |
| 디파이 예치·인출로 보이는 N건 — **예치를 양도로 볼지 확정 기준 없음.** 지금은 단순 입출금으로 읽었고, 연결 안 한 출금은 원가가 소멸한다. 같은 자산이 그대로 돌아온 것이면 「전송 연결」 화면에서 짝지어 달라 | 백서 U-05 · U-06 |

**자동으로 이어 붙이지 않는 이유**: 예치·인출을 자동으로 원가 이전으로 처리하면
근거 없이 세액이 **줄어든다.** 2026-10 국세청 고시 전까지는 사용자가 직접 잇게 둔다.

## 7. 파서 ID · detect

```text
id: trezor-suite-csv-v1
detect (앞 600자):
  - format == .csv
  - 필수 헤더 4개 전부 존재: Transaction ID, Amount unit, Fee unit, Address
  - "Fiat (" 있으면 0.96, 없으면 0.9
reject:
  - 헤더 불일치 → parserReject
  - RECV 행이 없어 내 지갑 주소를 못 찾음 → parserReject
```

네트워크는 **파일명**에서 읽는다: `bitcoin` → `BTC`, `ethereum` → `ETH`,
그 밖은 첫 행의 자산 코드.

## 8. 실측 패턴 (샘플 2개 · 값은 옮기지 않음)

| | Bitcoin 파일 | Ethereum 파일 |
|---|---|---|
| `Type` | `RECV` 만 | `RECV` + `SENT` |
| 자산 | 1종 | 원자산 3종 + **시세 없는 영수증 토큰 2종** |
| 한 TXID 에 여러 행 | 없음 (전부 1행) | **있음** (2행짜리 존재) |
| `Amount` 가 0 인 행 | 없음 | **있음** (승인 등) |
| `Fiat` 빈 행 | 없음 | **있음** (영수증 토큰) |
| `Fee` | 전부 0 (받기만 함) | 보낸 행에 있음 |
| `Label` · `Other` | 전부 빈 칸 | 전부 빈 칸 |

즉 **Bitcoin 파일은 단순 입금만, Ethereum 파일이 까다로운 경우를 전부 갖고 있다.**
파서를 고칠 때 회귀 확인은 Ethereum 쪽으로 해야 한다.

## 9. 합성 예시 (커밋용 · 실제 값 아님)

```csv
Timestamp,Date,Time,Type,Transaction ID,Fee,Fee unit,Address,Label,Amount,Amount unit,Fiat (USD),Other
1767225600,2026. 1. 1.,12:00:00,RECV,0xaaaa,0,,0xMYWALLET,,1,ETH,"3,000.00",
1767312000,2026. 1. 2.,12:00:00,SENT,0xbbbb,0.002,ETH,0xPOOL,,1000,USDT,"1,000.00",
1767312000,2026. 1. 2.,12:00:00,SENT,0xbbbb,0,,0xMYWALLET,,1000,rcptUSDT,,
1767398400,2026. 1. 3.,12:00:00,SENT,0xcccc,0.001,ETH,0xTOKEN,,0,USDT,,
```

읽는 법:

- 2행 — 받기. `Address` 가 내 지갑 → `deposit`
- 3·4행 — **같은 TXID**. 3행은 나간 것(`Address` 가 상대), 4행은 들어온 것(`Address` 가 내 지갑).
  들어온 쪽만 `Fiat` 가 비었으므로 **`trezor-defi-deposit`**. 가스비는 나간 3행에만 붙는다
- 5행 — `Amount` 0 + 가스비만 → **`trezor-gas-only`**, 소멸 표시

내 지갑 주소는 2행·4행의 `Address` 최빈값으로 잡힌다.

## 10. 보안

지갑 주소·TXID raw 커밋 금지. 앱은 `LedgerEvent.txidHash` 와 `meta["ownAddress"]` 에
**SHA-256 앞 16자**만 넣는다 — 감사 추적에는 같은 값이 같은 문자열로 나오면 충분하다.
