## 2. 거래구분 → LedgerEvent

| 거래구분 | type | base | quote / KRW |
|----------|------|------|-------------|
| 매수 | `buy` | 자산명 | 정산·거래금액이 KRW면 KRW 마켓 |
| 매도 | `sell` | 자산명 | 동일 |
| 입금 (가상자산) | `deposit` | 자산명 | |
| 출금 (가상자산) | `withdrawal` | 자산명 | 전송 매칭 소스 |
| 입금 (KRW) | `deposit` 또는 `fiat_deposit` | KRW | 원장 현금 유입 (코인 취득 아님) |
| 출금 (KRW) | `withdrawal` / `fiat_withdraw` | KRW | |

### 2.1 수수료

- 컬럼이 “정산금액 **(수수료 포함)**” 이므로:
  - 매수: `fee_krw ≈ |정산금액| − 거래금액` (정산이 더 큰 현금 유출)
  - 매도: `fee_krw ≈ 거래금액 − 정산금액` (정산이 더 작은 현금 유입)
- 취득원가(KRW): 매수 시 **|정산금액|** 사용이 안전 (수수료 포함 실지급).

### 2.2 출금 비고 (전송 매칭)

비고에 거래소 이름·주소 조각이 붙는 경우 있음 (예: 바이낸스).

- 자동 매칭 힌트: `비고`에 `바이낸스` / `OKX` 등  
- 주소 전문은 **로그·커밋 금지**, 매칭용 해시만 선택 저장

### 2.3 예치금 이용료

KRW **입금** + 비고 `예치금 이용료` → 이자성 소액.

- **가상자산 기타소득 원장과 분리** 권장 (`income` fiat 또는 별도 태그).  
- 동일 성격은 아래 원천징수 서류와 연결 가능.

## 3. 실측 분포 (첨부 1건 기준, 기간 예: 약 1년)

대략: 매수 53 · 입금 49 · 출금 22 · 매도 7  
비고: 지정가 매수 다수, USDT→바이낸스 출금 다수, 예치금 이용료 입금 소수.

사용자 플로우와 일치:

```text
KRW 입금 → USDT 매수(KRW) → USDT 출금(바이낸스) → (해외) → … → USDT 매도(KRW) → KRW 출금
```

## 4. 파서 구현 전략 (PDF 전용)

빗썸 거래내역은 **PDF 확인서만** 제공된다. 엑셀 경로는 v1에 두지 않는다.

| 옵션 | 내용 | 권장 |
|------|------|------|
| A | PDF 텍스트/테이블 추출 후 정규화 | **v1 필수** |
| B | 사용자 제네릭 매핑 (비표준) | 폴백 |

구현 메모:

1. `BithumbTransactionCertificateParser` — PDF import 전용.  
2. 2단 레이아웃(금액 행 + 단위 행), 거래일시 줄바꿈 병합.  
3. 암호 PDF: 사용자 비밀번호 입력 후 복호화 (키체인 저장 시 [macos-zero-trace] 정책 준수).  
4. 단위 테스트 fixture: **합성 텍스트/가짜 PDF만** (`docs/samples/synthetic/`, 개인정보 없음). 실 PDF 커밋 금지.  
5. 파싱 후 고객명·계좌·주소 등 PII 필드는 **폐기** (원장에 불필요).

### 4.1 detect

- 제목 `거래내역 확인서` + 헤더 `정산금액 (수수료 포함)`

## 5. 다른 빗썸 서류: 이자·배당 원천징수영수증

첨부 중 일부는 **거래내역이 아님**.

| 항목 | 내용 |
|------|------|
| 제목 | 이자·배당소득 원천징수영수증 (소득자보관용) |
| 징수의무자 | 주식회사 빗썸 |
| 내용 | 지급일, 이자소득 지급액, 세율(예 14%), 원천징수 소득세 등 |
| CoinTax v1 | **가상자산 양도 기타소득 엔진 밖** (이자소득·원천징수 영역) |
| 연동 | 예치금 이용료 입금 행과 기간·금액 대조 **참고 가능** (별도 모듈 later) |

## 7. 바이낸스·OKX와의 정합성

| 필요 데이터 | 빗썸 확인서 | 바이낸스 Spot xlsx | OKX Trading History |
|-------------|-------------|--------------------|---------------------|
| KRW↔코인 매매 | ✅ | ❌ (USDT 마켓) | ✅ Spot |
| 해외 전송 출금 | ✅ 출금 | ❌ (입출금 파일 필요) | ✅ Transfer |
| 해외 전송 입금 | ✅ 입금 | ❌ | ✅ Transfer |
| 체결 수수료 | 정산금액에 포함 | Fee/Fee Coin | Fee/Fee Unit |

**검토 결론:** 빗썸 확인서 + OKX Trading History 조합이면 국내↔해외 브릿지 추적에 핵심 이벤트가 잡힌다.  
바이낸스만 Spot 파일이면 **입금 측 누락** → Deposit/Withdrawal 추가 필요.
