## 0. 왜 했나

세법 백서([00-tax-law-ssot.md](./00-tax-law-ssot.md))를 법제처 원문으로 전수 대조하다가,
**앱이 폐지된 규정으로 계산하고 있다**는 것을 확인했다.

> `[영]` 소득세법 시행령 §88① (2025-02-28 개정 · 2027-01-01 시행)
> 가상자산을 양도함으로써 발생하는 소득에 대한 기타소득금액을 산출하는 경우에는
> **거주자별로 제92조제2항제4호의 총평균법**을 적용하여 계산한다.

앱은 「빗썸=이동평균법 / 그 밖=선입선출법, 계정×자산 단위」로 계산하고 있었다.
이는 2025-02-28 개정으로 **삭제된 옛 조문**이다. 국세청 홈페이지 안내가 2026-08 현재까지
옛 문구를 그대로 두고 있어 그것을 근거로 삼았던 것이 원인이다 (백서 6.3).

## 1. 무엇이 달라졌나 — 계산 규칙

| | 전 | 후 |
|---|---|---|
| 계산 단위 | 계정 × 자산 | **사람 × 자산** (거래소·지갑 구분 없음) |
| 방법 | 이동평균 / 선입선출 | **총평균법** |
| 단가 확정 시점 | 처분 즉시 | **과세기간 종료 후** (연말에 더 사면 그해 앞선 처분의 원가도 바뀐다) |
| 의제취득가 비교 | 계정별 · 평균/건별 선택 | **자산별 단가 하나** (매입 건 개념 소멸) |
| 끝수 | 1원 반올림 | **과세표준 1원 버림 · 세액 국세/지방세 각각 10원 버림** |
| 필요경비 의제 50% | 없음 | **자산별 on/off + 켰을 때·껐을 때 병기** |

구조는 **수량 장부(계정별)와 원가 풀(거주자별)을 분리**했다. 계정별 수량 추적은 전송 누락·
재고 부족 감지에 그대로 필요하고, §88① 이 정하는 것은 *원가 계산 단위*뿐이기 때문이다.

### 4번을 특히 기록해 둔다

순으로 고정했다. **결정성은 세금 계산에서 타협할 수 없다.**

## 3. 새로 들어온 것

**Trezor Suite CSV 파서** — 하드웨어 지갑 내역을 읽는다. 세 가지가 거래소 파일과 다르고,
셋 다 틀리면 수량·원가가 통째로 어긋난다.

1. **`Type` 만으로 방향을 판정할 수 없다.** 한 트랜잭션이 토큰을 내보내면서 다른 토큰을 받으면
   두 행 모두 `SENT` 로 찍힌다. 방향은 **`Address` 열**로 가른다 — 받는 행에는 내 지갑 주소가 적힌다.
   내 주소를 못 찾으면 **가져오지 않고 막는다.**
2. **한 트랜잭션이 여러 행**이다 (`Transaction ID` 로 묶는다).
3. **금액 0 + 수수료만** 있는 행이 있다 (토큰 사용 승인 등).

분류 결과를 `sourceKind` 로 남긴다 — 단순 입출금 / 가스비만 / 디파이 예치 / 디파이 인출 /
시세 없는 토큰. **세무 처리는 파서가 정하지 않는다** — 예치를 양도로 볼지(백서 U-05),
늘어나 돌아온 몫을 어떤 소득으로 볼지(U-06)는 2026-10 국세청 고시 대기다.

**신고 안내** — 세액 0원도 신고 대상(`[법]` §73①8), 지방소득세는 위택스에 따로,
신고 기간, Earn·렌딩 미포함. 화면·PDF·CSV 에 같은 문구를 같은 순서로 싣는다.

**필요경비 의제 50%** (`[법]` §37⑥) — 자산별 on/off. 조문의 세 요건을 지킨다:
선택이다 · 자산별 일괄이다 · 부대비용을 못 뺀다.

## 6. 이 회차가 남긴 규칙

1. **테스트 초록불은 「코드가 코드대로 돈다」이지 「숫자가 맞다」가 아니다.**
   이번에 잡은 8건 중 7건은 기존 테스트가 전부 통과하는 상태에서 나왔다.
2. **엔진과 다른 경로로 세운 등식만이 결함을 잡는다.** 원가 보존 테스트는 원본 이벤트에서
   직접 계산하고, 검증기의 V-COST-03 은 총액으로, 집계기는 건별로 계산한다 — 두 경로가
   달라야 검사가 성립한다.
3. **골든값을 고칠 때는 왜 그 숫자가 됐는지 손으로 계산한다.** 설명이 안 되면 거기서 멈춘다.
   이번에 46건을 갱신했고 전부 근거를 커밋 메시지에 적었다.
