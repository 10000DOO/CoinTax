## 2. 앱이 계산하는 핵심 공식

### 2.1 건별 실현손익 (양도)

```text
양도가액(KRW)     = 처분 대가의 KRW 환산액
취득가액(KRW)     = 원가 엔진이 배분한 취득원가 KRW
부대비용(KRW)     = 거래수수료·이체수수료 등 (정책에 따라)
건별소득          = 양도가액 − 취득가액 − 부대비용
```

### 2.2 연간 집계

```text
가상자산소득금액  = Σ 건별소득 (동일 과세연도, 이익·손실 통산)
과세표준          = max(0, 가상자산소득금액 − 기본공제)
산출세액(국세)    = 과세표준 × 20%
지방소득세        = 과세표준 × 2%   (또는 국세 × 10%)
예상 납부 합계    = 국세 + 지방소득세
```

소득금액이 기본공제 이하이면 과세표준·세액 0.

### 2.3 표시 예시

| 항목 | 금액(원) |
|------|----------|
| 총수입금액(양도가 합) | 100,000,000 |
| 필요경비(취득+부대) | 80,000,000 |
| 소득금액 | 20,000,000 |
| 기본공제 | 2,500,000 |
| 과세표준 | 17,500,000 |
| 국세 20% | 3,500,000 |
| 지방세 2% | 350,000 |
| **예상 합계** | **3,850,000** |

## 3. 과세 이벤트 vs 비교세 이동

사용자 플로우와 엔진 처리.

| 단계 | 이벤트 | v1 세금 처리 |
|------|--------|----------------|
| 국내 USDT 매수 | KRW→USDT | 취득 (원가 형성). 원화는 가상자산이 아니므로 양도 없음 |
| 국내→해외 USDT 전송 | 출금/입금 | **양도로 보지 않음** (동일 자산 이동, 원가 이전). 전송 수수료만 비용 정책 적용 |
| 해외 알트 매수 | USDT→ALT | ALT 취득 원가 형성 **+ 동시에 USDT 양도(처분)** |
| 해외 알트 매도 | ALT→USDT | **ALT 양도(처분)** → 실현손익 인식. 받은 USDT 는 그 시점 원화가액으로 취득 |
| 해외→국내 USDT 전송 | 출금/입금 | 원가 이전 (비과세 이동 가정) |
| 국내 USDT 매도 | USDT→KRW | **양도(처분)** → 실현손익 인식 |

### 3.0 코인 ↔ 코인 교환은 양도다 (양쪽 모두)

USDT 로 알트코인을 사면 **알트코인을 취득하는 동시에 USDT 를 양도한 것**이다.
소득세법 시행령 제88조가 가상자산 교환거래의 양도가액 산정 방법을 따로 정하고 있는 것이 근거다
(교환을 양도로 보지 않으면 그 조항이 필요하지 않다).

엔진은 매매의 **견적자산 leg** 을 반드시 원장에 반영한다.

```text
매수 (USDT → ALT):  ALT 입고(원가 = 견적 원화가액 + 수수료)  +  USDT 출고 → 처분손익 인식
매도 (ALT → USDT):  ALT 출고 → 처분손익 인식               +  USDT 입고(원가 = 견적 원화가액)
```

이 leg 을 빼면 **USDT 잔고가 줄지 않아** 보유 수량·평단·의제취득가·이후 손익이 모두 틀어진다
(실데이터에서 실제로 발생: `docs/realdata-audit-2026-08-12.md` F-08).

전체 경제적 이익 합계는 어느 해석에서든 같지만 **어느 과세연도에 귀속되는지**가 달라진다 → 세무 확인 항목 TQ-19.

**과세 시작 전 거래에도 환율이 필요하다.** 2026년에 ALT 를 팔아 받은 USDT 의 취득원가가
그 시점 원화가액이고, 그 값이 2026-12-31 의제취득가와 2027년 이후 손익의 출발점이 된다.
(원화 마켓 매매는 과세 대상일 때만 금액이 필요하다.)

### 3.1 이중과세 방지 (중요)

USDT를 해외에서 알트 매매에 쓰고, 다시 USDT로 바꾼 뒤 국내에서 원화 매도하면:

- 알트 매도 시점에 1차 실현  
- USDT→KRW 매도 시점에 2차 실현  

각 단계는 **그 시점 취득가** 기준으로 손익을 잡는다.  
전송 자체를 양도로 잡으면 **이중 계산**이 되므로, confirmed `TransferLink`로 묶인 입출금은 처분 목록에서 제외한다.

### 3.2 과세연도 귀속

- 기본: **처분(양도) 시점**의 연도  
- `taxStartDate` 이전 처분은 기본 리포트에서 제외(설정으로 포함 가능 — 시뮬레이션용)

## 4. 취득가액

### 4.1 실제 취득가

- 매수 대금(KRW 환산) + 취득 관련 수수료(정책)  
- 전송으로 들어온 자산: 출고 측에서 이전된 원가

### 4.2 의제 취득가 (확정)

```text
의제 = max( 2026-12-31 장부 실제 취득가, 2026-12-31 시가 )
```

| 항목 | v1 |
|------|-----|
| 실제 취득가·보유 수량 | **과거 전 거래 이력 재생**으로 자동 |
| 시가 | 조회/파일; 없으면 해당 자산 의제 **확정 차단** |
| 시가의 법령 정의 | **소득세법 시행령 제88조제2항** — ① 시가고시 가상자산사업자 취급 자산: 각 사업자 사업장에서 **2027-01-01 0시** 공시가격의 **평균** ② 그 외: 비(非)시가고시 사업자가 같은 시점 공시한 가격. 기준 시점이 「2026-12-31 종가」가 아님에 주의 |
| 시가 확보 경로 | 홈택스·손택스 「가상자산 일평균가격 조회」 |
| max 적용 | 엔진 자동, 포지션별 채택 사유 표시 |
| 비교 단위 | **보유 전체 평균이 기본**(보수적), 설정에서 **매입 건별** 전환. 두 방식 결과를 리포트에 함께 표시 — 세무 확인 대기 (앱 「세무 확인」 TQ-01) |
| 수동 의제 표 입력 | 기본 UX 아님 |

절차 상세: [05-decisions.md](./05-decisions.md) §8.

## 5. 원가 배분 방법 (확정)

### 5.1 법령·국세청 안내 (2026-08)

- 소득세법 시행령 제88조: **가상자산주소별**로 취득가액 평가  
- **신고수리가상자산사업자** 경유 거래 → **이동평균법**  
- **그 외** → **선입선출법**  
- 국세청 「거주자의 가상자산소득 과세 개요」 동일 취지 명시

### 5.2 앱 기본 적용

| 계정 | 방법 | 이유 |
|------|------|------|
| 빗썸 | **이동평균법** | 국내 신고수리 가상자산사업자 |
| 바이낸스, OKX | **선입선출법** | 국내 신고수리 사업자 외 |
| 전송 입고 | 출고 원가 이전 후, 도착 계정 방법에 편입 | 이중과세 방지 |

- 원장은 **계정 × 자산** 단위.  
- 리포트 필수 문구 예:  
  「빗썸 계정은 이동평균법, 바이낸스/OKX 계정은 선입선출법으로 계산했습니다.」  
- 일부 개정 논의의 **총평균법**은 현 국세청 안내와 다르므로 v1 미적용. 법령 변경 시 교체.

## 6. 통화 환산 (확정)

세금 표시·합산 통화: **KRW**

| 거래 | 규칙 |
|------|------|
| 빗썸 KRW 마켓 | 행의 KRW 금액 그대로 (환율 불필요) |
| USDT 등 외화연동 기축 | **외국환거래법 기준환율·재정환율** (교환·환산일) |
| 해외 현물 (USDT 견적) | v1: **USDT=USD 1:1** 후 해당일 **USD/KRW 기준환율** |

### 6.1 환율 확보 순서

1. 이벤트에 KRW 직기입 → 환율 불필요  
2. **자동 조회(기본 ON)** 한국은행 ECOS 일별 환율 (**인증키 필요**). 공개 시세 폴백은 기본 차단 → 로컬 캐시  
3. 실패·미고시 → **직전 고시일** (`FXHolidayPolicy`) 또는 **필요 날짜 목록** → 수동/CSV  
4. 휴일·미고시: **직전 고시일** 기준환율 + **적용 고시일(`sourceDate`)** 기록  
   - 근거: 국세청 서삼46015-11986(공휴일 → 전날 기준환율·재정환율), 가상자산 외화연동 기축의 기준환율 환산 준용  
   - 코드: `FXHolidayPolicy` (`previous_published_rate_v1`)

자동 조회는 거래 원본을 보내지 않고 **날짜·통화쌍만** 요청한다.

## 7. 부대비용·수수료

| 종류 | 처리 |
|------|------|
| 매수 수수료 | 취득가에 가산 (기본) |
| 매도 수수료 | **필요경비로 계상** (총수입금액은 총액). 전 계정 통일 — 세무 확인 대기 (TQ-02) |
| 입출금 네트워크 수수료(수량 소실) | **보수 `abandon_lost_cost`:** 도착 취득가·필요경비 미산입. 정책 플러그인으로 교체 가능 |
| 출금 시 별도 수수료(자산/KRW) | 동일 (v1) |
| 매수/매도 체결 수수료 | 취득가 가산 / 양도가 차감 |

**전송 소실 고지 (UI/export 필수):**

> 전송 소실 원가는 공개 세법 해설이 없어, 과다 공제를 피하기 위해 필요경비·도착 취득가에 넣지 않습니다. 세액이 다소 커질 수 있으며 세무 자문이 아닙니다.

구현: `TaxCopy.transferCost` 단일 상수. 정책 변경 시 문구·policy id 함께 교체 ([design/04-policies.md](./design/04-policies.md)).
